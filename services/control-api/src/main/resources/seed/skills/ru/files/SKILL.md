# Skill: files

Коннектор files позволяет один раз написать текстовый файл и дальше работать с ним: отчёт, который пользователь скачает; черновик, который вы доводите за несколько сообщений; HTML-страницу; таблицу в CSV. Файл адресуется id `agf_…`; id не меняется, а каждая запись становится новой версией под ним.

## Инструменты: что когда вызывать

- `save_file(content, name)` — новый файл. Тип задаёт имя: `.html`, `.md`, `.csv`, `.json`, всё остальное — простой текст. В `content` клади **весь** текст — ничего не дописывается за тебя.
- `save_file(content, fileId, name?)` — заменить весь текст существующего файла новой версией. Подходит, когда меняется бо́льшая часть текста; `name` переименовывает файл.
- `edit_file(fileId, edits)` — поменять часть файла: `[{oldText, newText}]`, применяются по порядку. `oldText` копируется из файла **дословно** — с пробелами и переносами — и должен встречаться **один раз**; если встречается дважды, возьми больше окружающего текста. Отклонённая правка не меняет ничего.
- `read_file(fileId, offset?, limit?)` — прочитать текстовый файл по строкам. Длинный файл приходит окнами: продолжай с `offset = nextOffset`, пока он не станет `null`. Картинки смотри через `read_image` из навыка media.
- `list_files(allConversations?, name?)` — найти файл, когда его id уже не перед глазами: по умолчанию в этом разговоре, `allConversations: true` — по всему аккаунту.

`save_file` и `edit_file` отвечают `{ file: { id, name, mime, size, version } }`.

## Как работать с файлом

- **Прочитай, прежде чем править.** `edit_file` работает с текущим текстом, а не с тем, что ты помнишь: после нескольких правок или если пользователь мог поменять файл — сначала прочитай.
- **Мелкая правка — `edit_file`, крупная — `save_file`.** Переписывать длинный файл ради одного абзаца — трата бюджета шагов и риск потерять текст по дороге.
- **«Файл сейчас пишет другой вызов или он изменился»** значит, что его записали в тот же момент: перечитай и повтори свою правку на новом тексте. Вслепую не перезаписывай.
- Предел — 1 МБ текста за одну запись. Для таблицы, которую пользователь хочет анализировать, лучше подходит навык sheets, а не CSV-файл.

## Как отдать файл пользователю

Вставь маркер в финальный ответ: `Отчёт готов: [[attach:agf_…]]` — маркер вырежется из текста, файл уедет вложением. **Без маркера пользователь файл не увидит.**

Вложение несёт версию, текущую на момент ответа: если потом поправишь файл, прежнее сообщение покажет прежний текст — приложи файл заново, чтобы показать новый.

Не каждый разговор принимает вложения: в ране без чата (задача по расписанию, событие доски) и в сессии IDE до пользователя ничего не дойдёт. Там скажи словами, что написал и где это найти.

## Важно

- **Файлы истекают** через какое-то время, и каждая запись отодвигает срок. Старый `agf_…` может вернуться как «file not found».
- Бинарные файлы (картинки, PDF, архивы) здесь не читаются и не правятся — их можно только переслать по id или приложить.
