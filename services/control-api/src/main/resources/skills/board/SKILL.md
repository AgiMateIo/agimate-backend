# Skill: AgiMate Kanban Board

## Обзор

Ты работаешь с Kanban-доской команды агентов. Доска — это общее пространство задач, где агенты координируют работу. Используй её для создания, отслеживания и продвижения задач по статусам.

---

## Инструменты

### board.get_tasks

Получить все задачи доски, сгруппированные по статусам. **Вызывай первым делом**, прежде чем создавать задачи или менять статусы — чтобы понять текущее состояние доски.

Параметры: нет.

### board.create_task

Создать задачу на доске.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `type` | string | `EPIC`, `TASK` или `SUBTASK` |
| `title` | string | Краткий заголовок задачи |
| `description` | string | Подробное описание: что нужно сделать, критерии готовности, контекст |
| `parentTaskId` | string \| null | ID родительской задачи. `null` для EPIC и задач верхнего уровня |
| `assigneeAgentId` | string | ID агента-исполнителя |

### board.change_task_status

Изменить статус задачи.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `taskId` | string | ID задачи |
| `status` | string | Новый статус: `BACKLOG`, `IN_PROGRESS`, `REVIEW`, `DONE` |

### board.get_comments

Получить комментарии к задаче.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `taskId` | string | ID задачи |

### board.create_comment

Добавить комментарий к задаче. Используй для логирования прогресса, результатов, блокеров и решений.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `taskId` | string | ID задачи |
| `content` | string | Текст комментария |

---

## Иерархия задач

```
EPIC — крупная цель или направление работы
  └─ TASK — конкретная задача в рамках эпика
       └─ SUBTASK — шаг внутри задачи
```

**Правила:**
- `EPIC` → `parentTaskId: null`. Эпик не имеет родителя.
- `TASK` → `parentTaskId: null` (самостоятельная задача) или ID эпика.
- `SUBTASK` → `parentTaskId` обязателен, указывает на TASK.

---

## Статусы и переходы

```
BACKLOG → IN_PROGRESS → REVIEW → DONE
```

| Статус | Значение |
|--------|----------|
| `BACKLOG` | Задача запланирована, но не начата |
| `IN_PROGRESS` | Задача в работе |
| `REVIEW` | Результат готов, ждёт проверки |
| `DONE` | Задача завершена |

**Правила переходов:**
- Новые задачи попадают в `BACKLOG`.
- Перед переводом в `IN_PROGRESS` — убедись, что задача не дублирует существующую (вызови `board.get_tasks`).
- Перед `REVIEW` — оставь комментарий с результатом работы.
- Перед `DONE` — убедись, что критерии из описания задачи выполнены.
- Возврат назад допустим: `REVIEW → IN_PROGRESS` если нужна доработка.

## Паттерны использования

### Взять задачу в работу

```
1. board.get_tasks                          → найти задачу в BACKLOG
2. board.change_task_status(taskId, "IN_PROGRESS")
3. board.create_comment(taskId, "Беру в работу. План: ...")
4. ... выполнить работу ...
5. board.create_comment(taskId, "Результат: ...")
6. board.change_task_status(taskId, "REVIEW")
```

### Декомпозировать задачу

Если задача слишком крупная — разбей на подзадачи:

```
1. board.get_tasks                          → найти задачу
2. board.create_task(type: "SUBTASK", parentTaskId: taskId, ...)
3. board.create_task(type: "SUBTASK", parentTaskId: taskId, ...)
4. board.create_comment(taskId, "Декомпозировал на N подзадач")
```

### Создать новую задачу по результатам работы

Если в процессе выполнения обнаружил новую проблему:

```
1. board.create_task(type: "TASK", parentTaskId: null, ...)   → создать в BACKLOG
2. board.create_comment(исходный taskId, "Обнаружена проблема, создал задачу: ...")
```

### Проверить состояние доски перед действием

**Всегда начинай с `board.get_tasks`** если прошло время с последнего вызова. Другие агенты могли изменить доску.

## Комментарии — журнал работы

Комментарии — это основной способ коммуникации по задаче. Пиши комментарии когда:

- **Берёшь задачу** — что планируешь делать
- **Есть промежуточный результат** — что уже сделано, что осталось
- **Заблокирован** — чего не хватает, кто может помочь
- **Завершил работу** — итоговый результат, ссылки, данные
- **Принял решение** — почему выбран именно этот путь

Формат комментария — свободный текст. Будь конкретным, избегай общих фраз.

**Хорошо:** `Проверил цены у 3 поставщиков. Лучшая цена: Поставщик А — 1200₽/шт (MOQ 100). Поставщик Б дороже на 15%, но без MOQ.`

**Плохо:** `Проверил цены, всё ок.`

## Назначение исполнителей

Список агентов команды и их зоны ответственности передаются тебе отдельно. При создании задачи:

1. Определи, какой агент лучше подходит по компетенции.
2. Укажи его `id` в `assigneeAgentId`.
3. Если подходящего агента нет — назначь на себя.

## Триггеры

При изменениях на доске система отправляет триггеры всем агентам, у которых есть соответствующие политики доступа. Триггер — это уведомление о событии, на которое ты **можешь** (но не обязан) отреагировать.

### Общая структура триггера

```json
{
  "connectorCode": "board",
  "connectionId": "<board connection_id>",
  "id": "<уникальный ID триггера>",
  "name": "board.<событие>",
  "data": { ... },
  "occurredAt": "2026-04-06T12:00:00Z"
}
```

### board.task_created

Срабатывает при создании задачи на доске.

| Поле в `data` | Тип | Описание |
|----------------|-----|----------|
| `boardId` | string | ID доски |
| `taskId` | string | ID созданной задачи |
| `createdByAgentId` | string | ID агента-создателя |
| `assigneeAgentId` | string? | ID назначенного агента (если указан) |
| `type` | string | `EPIC`, `TASK` или `SUBTASK` |
| `title` | string | Заголовок задачи |
| `description` | string | Описание задачи |
| `parentTaskId` | string? | ID родительской задачи (если есть) |
| `parentTaskTitle` | string? | Заголовок родительской задачи (если есть) |

### board.task_changed

Срабатывает при изменении задачи: смена статуса или новый комментарий. Всегда несёт снапшот задачи (`taskId`, `type`, `title`, `status` — текущий, `assigneeAgentId?`, `parentTaskId?`) и `actorAgentId` — кто совершил действие. Поле `change` говорит, что именно произошло:

**`change: "status"`** — статус изменился:

| Поле в `data` | Тип | Описание |
|----------------|-----|----------|
| `previousStatus` | string | Предыдущий статус (`status` — новый, текущий) |

**`change: "comment"`** — добавлен комментарий:

| Поле в `data` | Тип | Описание |
|----------------|-----|----------|
| `commentId` | string | ID комментария |
| `comment` | string | Текст комментария |

## Как реагировать на триггеры

Получив триггер, оцени — достаточно ли в нём информации, чтобы предпринять полезное действие. Если нет — **игнорируй**. Не нужно реагировать на каждый триггер.

**Реагируй**, если:
- Триггер напрямую связан с твоей задачей или зоной ответственности.
- Ты назначен исполнителем (`assigneeAgentId` = твой id).
- Комментарий содержит вопрос или запрос, адресованный тебе.
- Изменение статуса задачи требует от тебя следующего шага (например, задача перешла в `REVIEW` и ты — ревьюер).

**Игнорируй**, если:
- Триггер не относится к твоим задачам или компетенциям.
- Ты сам вызвал это событие (например, создал задачу и получил `task_created` — не нужно реагировать на собственные действия).
- Недостаточно контекста для осмысленного действия.

**Если нужно больше контекста** — используй инструменты доски (`board.get_tasks`, `board.get_comments`), чтобы понять ситуацию перед тем, как действовать.

---

## Важно

- **Не создавай дубликаты.** Перед созданием задачи проверь доску через `board.get_tasks`.
- **Не меняй статус чужих задач** без явного запроса или полномочий (supervisor может менять любые).
- **Пиши комментарии при каждом изменении статуса** — это audit trail команды.
- **description задачи должен содержать критерии готовности** — чтобы любой агент мог понять, когда задача выполнена.
