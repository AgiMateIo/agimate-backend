# Skill: AgiMate Memory

## Обзор

Память даёт тебе **долговременные знания**, переживающие отдельные сессии: предпочтения пользователя, факты о нём, договорённости, важные решения и контекст, к которому стоит возвращаться.

Память двухслойная:

- **cold** — свёрнутая, вычищенная память (один файл). Она **уже подмешана в твой контекст** — тебе не нужно её специально запрашивать, чтобы что-то вспомнить.
- **hot** — заметки: короткие сырые факты, которые ты добавляешь по ходу диалога. Позже они автоматически консолидируются в cold.

Главное в повседневной работе — **вовремя сохранять заметки** (`persist-memory.save_memory_note`). Свёртку и переписывание памяти за тебя инициируют триггеры (см. ниже) — вручную этим заниматься не нужно.

---

## Когда сохранять заметку

Вызывай `persist-memory.save_memory_note`, как только во время диалога появляется что-то, что стоит помнить **в будущих разговорах**:

- пользователь прямо просит запомнить («запомни, что…», «на будущее…», «я предпочитаю…»);
- всплывает устойчивый факт о пользователе: имя, роль, часовой пояс, проекты, предпочтения, ограничения;
- принято решение или договорённость, к которым вы будете возвращаться;
- выяснился важный контекст, который не очевиден из cold-памяти и пригодится потом.

**Особенно — негативные сигналы** (раздел «Чего избегать»). Их легко пропустить, а ценность высокая — они предотвращают повтор ошибок:

- пользователь **поправил тебя** или переделал твою работу — сохрани, что именно было не так и как надо («не оборачивай ответ в лишние пояснения», «коммить без трейлера Co-Authored-By»);
- выразил **недовольство или раздражение** — сохрани триггер реакции («раздражается, когда переспрашиваю очевидное»);
- задал **жёсткое ограничение/запрет** («никогда не пушь в master напрямую», «всегда сначала покажи план»);
- ты **ошибся**, и это указали — сохрани антипаттерн как урок, чтобы не наступить повторно.

Правила:

- **Приоритет — `persist-memory.save_memory_note`.** Если сомневаешься, сохранять или нет, — сохраняй. Заметки дешёвые и append-only.
- **Не упускай негатив.** Правки, недовольство и запреты сохраняй так же охотно, как позитивные факты, — формулируй как «избегать X» / «всегда Y».
- **Одна заметка — один самодостаточный факт.** Пиши так, чтобы будущий «ты» понял её без контекста диалога. Плохо: «он согласился». Хорошо: «Пользователь согласовал релиз модуля биллинга на 2026-07-01».
- **Не бойся дублей и противоречий** — консолидация сведёт повторы и разрешит конфликты. Не перечитывай память, чтобы проверить, нет ли уже такого факта.
- **Не сохраняй мусор**: одноразовые реплики, сиюминутные детали задачи, то, что не пригодится за пределами текущего разговора.

## Инструменты

### persist-memory.save_memory_note

Добавить заметку в hot-память (append). Основной инструмент памяти в диалоге.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `text` | string | Факт/заметка для запоминания — самодостаточная формулировка |
| `sessionId` | string? | Сессия-источник (для трейсинга); при обработке `persist-memory.notes_by_session` передавай `sessionId` из триггера |

Возвращает `{ "id": "<id заметки>" }`.

### persist-memory.get_memory_notes

Получить ещё не сконсолидированные заметки (hot). В обычном диалоге не нужен — пригождается при консолидации, чтобы свериться с накопленным.

Параметры: нет. Возвращает `{ "notes": [ { "id", "content", "sessionId" } ] }`.

### persist-memory.get_memory

Получить свёрнутую (cold) память и её `version`. **Не вызывай ради припоминания** — cold уже в твоём контексте. Нужен в основном при консолидации: прочитать текущую память и получить `version` для `persist-memory.update_memory`.

Параметры: нет. Возвращает `{ "content": "<MD>", "version": <int> }`.

### persist-memory.update_memory

Переписать cold-память целиком. Используется при консолидации. Передавай `version` из `persist-memory.get_memory` (оптимистическая блокировка). Если передан `consolidationId`, заметки этой партии удаляются **в той же транзакции** — атомарно со свёрткой.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `text` | string | Полное новое содержимое cold-памяти |
| `version` | int? | Ожидаемая текущая версия из `persist-memory.get_memory` (обязательна, если память уже существует) |
| `consolidationId` | string? | Id из триггера `persist-memory.consolidate` — удаляет свёрнутые заметки |

При конфликте версии вернётся ошибка «memory changed: re-read and retry» — перечитай `persist-memory.get_memory` и повтори.

## Структура cold-памяти

cold лежит в твоём контексте **каждый ход**, поэтому держи её компактной и предсказуемой. При консолидации укладывай факты в фиксированные разделы (в этом порядке), **пустые — опускай**:

```markdown
# Память

## Профиль
- Стабильные факты о пользователе: имя, роль, часовой пояс, язык, домен, ключевые проекты/сущности.

## Предпочтения
- Как пользователь хочет, чтобы ты общался и работал: тон, объём и формат ответов, язык, стиль кода,
  степень автономии («делай сам» vs «сначала спроси»).

## Чего избегать
- Раздражители, повторяющиеся правки, жёсткие запреты («никогда не …»). Самое ценное знание —
  оно предотвращает повтор ошибок.

## Приёмы и инструменты
- Усвоенные операционные знания: какие тулы/последовательности работают, подводные камни,
  особенности окружения, правила вида «если X — делай Y».

## Рабочий контекст
- Текущие цели, активные задачи/проекты, принятые решения и договорённости. Изменчивый раздел —
  при консолидации убирай завершённое и неактуальное.

## Глоссарий
- Проектные термины, сокращения, названия сущностей в лексиконе пользователя (опционально).
```

Правила:

- **Один пункт — один атомарный факт**, одна строка, маркированный список.
- **Компактность важнее полноты.** Обобщай и сливай родственные пункты, не наращивай список; противоречия разрешай в пользу более свежего.
- Разделы 1-3 — про персонализацию (общаться лучше), 4-6 — про исполнение (работать лучше).
- **Не дублируй** то, что и так есть в системном промпте или других скиллах.
- **Рабочий контекст устаревает** — вычищай выполненное при каждой консолидации.

## Триггеры

### persist-memory.notes_by_session

Просьба собрать заметки по одной сессии (издаётся раз в сутки по сессиям с активностью за последние 24 часа). Адресован **только тебе**.

```json
{
  "connectorCode": "persist-memory",
  "name": "persist-memory.notes_by_session",
  "data": {
    "sessionId": "<id сессии>",
    "messages": [ { "turnIdx": 0, "kind": "REQUEST", "text": "..." } ]
  }
}
```

### persist-memory.consolidate

Просьба свернуть накопленные заметки в cold-память (издаётся раз в час, если есть несконсолидированные заметки). Адресован **только тебе**.

```json
{
  "connectorCode": "persist-memory",
  "name": "persist-memory.consolidate",
  "data": {
    "consolidationId": "<id партии>",
    "notes": [ { "id", "content", "sessionId" } ]
  }
}
```

## Как реагировать на триггеры

Скилл активнее всего именно в момент триггеров.

### На `persist-memory.notes_by_session`

1. Прочитай `data.messages` — это диалог одной сессии.
2. Выдели факты, которые стоит помнить в будущем (см. «Когда сохранять заметку»).
3. По каждому вызови `persist-memory.save_memory_note(text: "<факт>", sessionId: data.sessionId)`.
4. Если в сессии нет ничего достойного запоминания — просто ничего не сохраняй.

Не переписывай cold напрямую отсюда — этим займётся консолидация.

### На `persist-memory.consolidate`

1. `persist-memory.get_memory()` → текущий cold-`content` и `version`.
2. Слей `data.notes` с текущим cold по разделам из «Структура cold-памяти»: разложи новые факты по нужным разделам, **убери дубли и устаревшее, разреши противоречия** в пользу более свежего, вычисти завершённое из «Рабочего контекста». Держи память компактной.
3. `persist-memory.update_memory(text: "<обновлённый MD>", version: <из persist-memory.get_memory>, consolidationId: data.consolidationId)` — это запишет cold и удалит свёрнутые заметки за один шаг.
4. При ошибке конфликта версии — перечитай `persist-memory.get_memory` и повтори шаг 3 (заметки никуда не делись).

---

## Важно

- **Cold-память уже в контексте.** Не вызывай `persist-memory.get_memory`/`persist-memory.get_memory_notes` ради припоминания — это нужно только при консолидации.
- **Сохраняй заметки активно.** `persist-memory.save_memory_note` — приоритетный инструмент; при сомнении сохраняй.
- **Заметки самодостаточны.** Их прочтут вне контекста текущего диалога — формулируй полно.
- **Свёртку не инициируй вручную.** Заметки превращаются в cold по триггеру `persist-memory.consolidate`; твоя задача в диалоге — только аккуратно их накапливать.
- **При консолидации передавай `version` и `consolidationId`**, а на конфликт версии — перечитай и повтори.
