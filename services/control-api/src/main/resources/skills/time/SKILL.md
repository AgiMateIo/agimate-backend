# Skill: AgiMate Time

## Обзор

Time-коннектор даёт тебе две вещи: узнать **текущее время** и **запланировать отложенную задачу самому себе**. Запланированная задача «будит» тебя в нужный момент с заданным промптом — так ты можешь поставить напоминание, организовать периодический мониторинг или запуск по расписанию, не держа контекст активным всё это время.

Всё время — в **UTC**.

---

## Инструменты

### time.current_datetime

Получить текущие дату и время в UTC (формат ISO-8601). Вызывай, когда нужно понять «сколько сейчас» — например, перед расчётом задержки или прежде чем планировать задачу.

Параметры: нет.

Возвращает:

| Поле | Тип | Описание |
|------|-----|----------|
| `dateTime` | string | Текущее время, ISO-8601 со смещением (например `2026-06-10T14:30:00Z`) |
| `zone` | string | Всегда `UTC` |

### time.schedule

Запланировать отложенную задачу для **себя**. Когда придёт срок, ты «проснёшься» с триггером `time.due`, в котором будет переданный `prompt`.

Укажи **ровно один** из режимов: `delaySeconds`, `intervalSeconds` или `cron`.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `prompt` | string | Что именно ты должен сделать, когда задача сработает. Пиши конкретно — это всё, что ты получишь в момент срабатывания |
| `delaySeconds` | long? | Сработать **один раз** через столько секунд от текущего момента |
| `intervalSeconds` | long? | Срабатывать **периодически** каждые столько секунд |
| `cron` | string? | Срабатывать по **cron-расписанию** (Spring, 6 полей — с секундами) |
| `zone` | string? | Таймзона для `cron`, IANA-идентификатор (по умолчанию `UTC`) |

Возвращает:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Id запланированной задачи (нужен для отмены) |
| `taskType` | string | `ONETIME`, `PERIODIC` или `CRON` |
| `nextRunAt` | string | Время ближайшего срабатывания |

### time.scheduled_tasks

Получить список твоих активных (ещё не завершённых) запланированных задач. Вызывай, чтобы проверить, что уже запланировано, прежде чем создавать дубликат.

Параметры: нет.

Возвращает `tasks` — список объектов:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | Id задачи |
| `taskType` | string | `ONETIME`, `PERIODIC` или `CRON` |
| `nextRunAt` | string | Время ближайшего срабатывания |
| `prompt` | string | Промпт, с которым задача тебя разбудит |
| `config` | object | Параметры режима (`intervalSeconds` / `cron` + `zone`) |

### time.cancel_scheduled

Отменить одну из своих запланированных задач по id. Используй для периодических/cron-задач, которые больше не нужны, — иначе они продолжат срабатывать.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string | Id задачи (из `time.schedule` или `time.scheduled_tasks`) |

Возвращает `{ "cancelled": true, "id": "<id>" }`.

## Режимы планирования

| Режим | Параметр | Тип задачи | Когда использовать |
|-------|----------|-----------|--------------------|
| Однократно | `delaySeconds` | `ONETIME` | Разовое напоминание/действие через заданную паузу |
| Периодически | `intervalSeconds` | `PERIODIC` | Регулярная проверка через равные интервалы |
| По расписанию | `cron` | `CRON` | Привязка к конкретному времени суток/дням (cron) |

**Правила:**
- Задавай **ровно один** из `delaySeconds` / `intervalSeconds` / `cron`. Ни ноль, ни два сразу.
- Все значения секунд должны быть **положительными**.
- `cron` — формат Spring из 6 полей (с секундами), например `0 0 9 * * *` — каждый день в 09:00. По умолчанию в `UTC`; для другого времени укажи `zone` (IANA, например `Europe/Moscow`).
- `PERIODIC` и `CRON` срабатывают **бесконечно**, пока ты их не отменишь через `time.cancel_scheduled`.

## Паттерны использования

### Поставить разовое напоминание

```
1. time.schedule(prompt: "Проверить, ответил ли поставщик на запрос цены", delaySeconds: 3600)
   → через час придёт time.due с этим prompt
```

### Периодический мониторинг

```
1. time.schedule(prompt: "Проверить новые задачи в BACKLOG и взять подходящую", intervalSeconds: 1800)
   → каждые 30 минут будешь просыпаться и проверять
2. ... когда мониторинг больше не нужен ...
3. time.scheduled_tasks                      → найти id задачи
4. time.cancel_scheduled(id)                 → остановить
```

### Запуск по расписанию (cron)

```
1. time.schedule(prompt: "Собрать дневной отчёт по доске", cron: "0 0 18 * * MON-FRI", zone: "Europe/Moscow")
   → по будням в 18:00 по Москве
```

### Не плодить дубликаты

```
1. time.scheduled_tasks                      → посмотреть, что уже запланировано
2. ... планировать новое, только если похожей задачи ещё нет ...
```

## Триггеры

### time.due

Срабатывает, когда наступает срок задачи, созданной через `time.schedule`. Адресован **только тебе** — тому агенту, который эту задачу запланировал.

```json
{
  "connectorCode": "time",
  "id": "<уникальный ID триггера>",
  "name": "time.due",
  "data": { "prompt": "<твой текст из time.schedule>" },
  "occurredAt": "2026-06-10T14:30:00Z"
}
```

| Поле в `data` | Тип | Описание |
|----------------|-----|----------|
| `prompt` | string | Текст, который ты сам задал при планировании |

---

## Как реагировать на триггеры

`time.due` — это **твоё собственное** отложенное напоминание. Получив его:

1. Прочитай `data.prompt` — это инструкция, которую ты оставил себе ранее.
2. Выполни описанное действие.
3. Если задача была `ONETIME` — она уже завершена, ничего отменять не нужно.
4. Если это был `PERIODIC`/`CRON` и больше повторять не нужно — отмени через `time.cancel_scheduled`.

---

## Важно

- **Время — в UTC.** Учитывай это при расчёте задержек и при чтении `dateTime`.
- **Ровно один режим** на вызов `time.schedule` — `delaySeconds` ИЛИ `intervalSeconds` ИЛИ `cron`.
- **`prompt` — самодостаточен.** В момент срабатывания у тебя будет только он, без текущего контекста. Пиши так, чтобы будущий «ты» понял, что делать.
- **Периодические и cron-задачи живут, пока их не отменишь.** Подчищай ненужные через `time.cancel_scheduled`, проверяя список через `time.scheduled_tasks`.
- **Не плоди дубликаты** — перед планированием свериcь с `time.scheduled_tasks`.
