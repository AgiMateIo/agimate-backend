# Skill: AgiMate Media

## Обзор

Media-коннектор даёт тебе способности, которых может не быть у твоей основной модели: **нарисовать картинку**, **изменить существующую** и **посмотреть на изображение**. Под капотом каждый тул вызывает отдельную модель с нужной способностью — тебе не нужно знать какую, она подбирается автоматически (или задана владельцем агента).

Файлы ходят **по ссылке**: у каждого файла есть id вида `agf_…`. Ты — курьер ссылок: получил `agf_…` из одного тула — передал его в другой или приложил к ответу. Байты через тебя не проходят.

---

## Инструменты

### media.gen_image

Сгенерировать изображение по текстовому описанию.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `prompt` | string | Детальное описание картинки: что изображено, стиль, композиция, фон |

Возвращает:

| Поле | Тип | Описание |
|------|-----|----------|
| `file` | object? | `{ "id": "agf_…", "mime": "image/png", "size": 384211 }` — ссылка на готовую картинку |
| `text` | string? | Комментарий модели; если `file` отсутствует — модель отказалась рисовать, и здесь причина |

### media.edit_image

Сделать изменённую версию существующей картинки: поменять фон, стиль, добавить/убрать объекты. Оригинал не изменяется — возвращается новый файл.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `fileId` | string | Id исходной картинки (`agf_…`) |
| `prompt` | string | Что изменить |

Возвращает то же, что `media.gen_image`.

### media.read_image

Посмотреть на изображение: описать его или ответить на вопрос о нём. Используй для файлов из истории, скриншотов с устройств и только что сгенерированных картинок.

| Параметр | Тип | Описание |
|----------|-----|----------|
| `fileId` | string | Id картинки (`agf_…`) |
| `question` | string? | Вопрос о картинке; без него — подробное описание |

Возвращает `{ "answer": "<текст>" }`.

**Не нужен**, если изображения поданы тебе напрямую — системная подсказка в диалоге говорит, видишь ли ты приложенные картинки сам. Если сказано, что не видишь, — читай их через `read_image` по id.

---

## Как отдать картинку пользователю

Вставь маркер в **финальный ответ**:

```
Готово, вот логотип: [[attach:agf_0198c2f4…]]
```

Маркер вырежется из текста, а файл уедет вложением (в Telegram — фото, в webchat — картинка в чате). Без маркера пользователь картинку **не увидит** — id сам по себе ничего не отправляет.

## Паттерны

### Нарисовать и отдать

```
1. media.gen_image(prompt: "минималистичный логотип кофейни, тёплые тона, плоский стиль")
   → { "file": { "id": "agf_A" } }
2. Ответ: "Вот логотип: [[attach:agf_A]]"
```

### Доработать по фидбеку

```
1. пользователь: "фон сделай тёмным"
2. media.edit_image(fileId: "agf_A", prompt: "тёмный фон, остальное не менять")
   → { "file": { "id": "agf_B" } }
3. Ответ: "Обновил: [[attach:agf_B]]"
```

### Понять, что на скриншоте

```
1. тул устройства вернул скриншот → { "file": { "id": "agf_S" } }
2. media.read_image(fileId: "agf_S", question: "какая ошибка на экране?")
   → { "answer": "…" }
```

## Важно

- **Промпт — на совесть.** Модель видит только твой `prompt`: перенеси в него детали из запроса пользователя (объект, стиль, цвета, текст на картинке), не заставляй её угадывать.
- **Отказ — не сбой.** Если в ответе только `text` без `file`, модель отказалась (например, по политике контента) — перескажи причину пользователю, не повторяй запрос как есть.
- **Файлы протухают.** У `agf_…` есть срок жизни; старый id из давней истории может вернуть «file not found» — тогда сгенерируй заново.
- **Ошибка «no model capable…»** значит, что подходящей модели не настроено — посоветуй пользователю добавить провайдера с image/vision-моделью или задать её агенту явно.
- Генерация занимает от десятков секунд до нескольких минут — это нормально, не дёргай тул повторно, пока не пришёл результат.
