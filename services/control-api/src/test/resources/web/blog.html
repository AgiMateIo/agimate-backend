Виртуальные потоки появились в Java 21, и с ними блокирующий код снова стал дешёвым, если не держать монитор во время ввода-вывода.

Посмотрим на простой пример, где тысячи задач ждут сеть, и сравним с пулом платформенных потоков, чтобы понять разницу на практике.

try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    executor.submit(() -> fetch(url));
}

Главное правило: не пинить поток и использовать ReentrantLock вместо synchronized вокруг блокировок.

  1. Замерьте текущую пропускную способность.
  2. Переключите исполнитель:
    • для HTTP-клиента;
    • для JDBC.
