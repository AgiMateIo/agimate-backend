# Исходящий HTTP по пользовательскому адресу

Есть класс вызовов, где адрес выбирает пользователь, а запрос делает наш сервер из нашей сети:

| Что | Кто задаёт адрес | Что уезжает | Что возвращается пользователю |
|-----|------------------|-------------|-------------------------------|
| Доставка вебхука агента (`WebhookTransport`) | `agents.webhook_url` | payload рана + заголовок авторизации | код ответа и текст ошибки в `webhook_delivery_logs` |
| Список моделей провайдера (`LlmDiscoveryHttp`) | `llm_providers.base_url` | api-ключ | распарсенный список моделей, а при не-2xx — первые 256 символов тела |
| Медиа-тулы (`MediaInferenceHttp`, `MediaEndpointTransport`) | `llm_providers.base_url` | api-ключ + промпт | картинка, текст, тело ошибки |
| Картинка из ответа провайдера (`RemoteImageFetcher`) | ответ провайдера | — | байты картинки |
| MCP-сервер (`McpClient`, `OAuthHttpClient`) | конфиг подключения | токен, код авторизации | результат тула |
| LLM-вызов агентного цикла (agent-worker, `ModelFactory`) | `base_url` из кредов | api-ключ + промпт | ответ модели — **в историю агента** |

Без гарда каждая строка — примитив request forgery: сервер ходит по внутренней сети, а часть строк
ещё и отдаёт ответ обратно тому, кто адрес выбрал. Последняя строка — худшая: промпт может быть
написан кем угодно, кто пишет агенту, и ответ он же и прочитает.

## Гард

`ru.agimate.common.net.PublicTargets` — единственный ответ на вопрос «можно ли открыть соединение
на этот адрес». У него две половины, и нужны обе:

- **`requireAllowed(url)`** — проверка URL до запроса: схема `http(s)`, есть хост, нет `userinfo`,
  и все адреса имени публично маршрутизируемы. Это половина, которая даёт понятный отказ.
- **`resolve(host)`** — та же проверка, вшитая в резолвер имён самого HTTP-клиента. Это половина,
  которая делает отказ правдой: проверка отдельно и резолв клиентом — два разных запроса к DNS, и
  имя вправе ответить публичным адресом на первый и приватным на второй (DNS rebinding).

Непубличным считается: loopback, any-local, link-local (включая `169.254.169.254`), site-local,
multicast, IPv6 unique-local `fc00::/7`, `0.0.0.0/8` и CGNAT `100.64.0.0/10` — последний выглядит
маршрутизируемым, но им не является. IPv4-mapped IPv6 отдельного случая не требует: `InetAddress`
возвращает для него `Inet4Address`.

Есть и третья, дешёвая половина — **`requireSyntax(url)`**: форма URL плюс адрес, если хост и есть
адрес. Её зовут на записи (`agents.webhook_url`, `llm_providers.base_url`), чтобы опечатка была 400
перед тем, кто её сделал. Резолв там намеренно не делается: сохранение формы не должно зависеть от
DNS, а ответ, который имеет значение, даётся всё равно в момент запроса.

## Как это подключено

- **control-api** — `PublicOnlyHttp` (`service/http`): один пул соединений на Apache HttpClient 5 с
  резолвером из `PublicTargets` и `disableRedirectHandling()`. Редиректы не следуем нигде: `302`
  переносит запрос на адрес, который никто не проверял. Клиенты берут отсюда `RestClient`
  (`LlmDiscoveryHttp`, медиа-транспорты, `RemoteImageFetcher`, `McpClient`, `OAuthHttpClient`).
- **Доставка вебхука** — OkHttp с `PublicOnlyDns` и `followRedirects(false)`. Отказ виден владельцу
  агента в логе доставки, поэтому его текст не называет адрес, в который разрезолвилось имя: иначе
  гард сам стал бы тем оракулом внутренней сети, ради которого его и ставили.
- **agent-worker** — клиент Spring AI не отдаёт ни DNS-хука, ни выключателя редиректов, поэтому
  адрес проверяется на уже соединённом сокете: `PublicOnlySslSocketFactory` отказывает до TLS-
  рукопожатия, то есть до того, как уйдёт хоть один байт запроса. Из этого следует требование
  `https` для провайдера: по plain http TLS-сокета не создаётся и проверка не срабатывает. Плюс
  `requireAllowed` на каждом вызове — кэш моделей иначе выверял бы адрес раз в полчаса.

Флаг `app.net.allow-private-targets` (в воркере — `agent.net.allow-private-targets`, default
`false`) снимает проверку целиком для локальной разработки, где интересные цели как раз на
loopback. Именно снимает, а не смягчает: половинчатый гард труднее держать в голове, чем его
отсутствие.

## Гард доверия

Адрес и подпись — разные слои: `PublicTargets` отвечает, **куда** позволено открыть соединение,
`ru.agimate.common.net.OutboundTrust` — **чью** подпись мы примем на той стороне. Второй появился
из-за серверов с совершенно обычной цепочкой, корня которой нет в `cacerts`: `Russian Trusted Root
CA` под MCP-сервером T-Invest и под доброй половиной российских API, куда может указывать и
`base_url` провайдера, и `webhook_url` агента.

Слияние делается **в одном `KeyStore`**: платформенные якоря плюс наши, и на выходе — штатный
`X509ExtendedTrustManager` самой JDK. Своего кода проверки доверия нет; добавляются только якоря,
имя хоста и срок проверяются как раньше. Платформенный набор читается через
`PublicOnlySslSocketFactory.defaultTrustManager()`, поэтому ни пути к `cacerts`, ни пароля
`changeit` здесь не встречается.

- **Откуда берутся** — свойство `app.net.trusted-ca` (в воркере `agent.net.trusted-ca`): адреса
  ресурсов Spring через запятую, `classpath:` для того, что несёт сборка, `file:` для того, что
  монтирует установка. Ресурс, а не путь, потому что у контейнеров приложений нет ни одного тома, и
  путь пришлось бы держать разным для compose, чарта и `bootRun` на хосте. Разбирает их
  `OutboundTrustLoader` — один на оба сервиса.
- **Пусто по умолчанию.** Сборка несёт `classpath:certs/russian-trusted-root.pem`, но включают его
  снаружи — `ops/compose.yaml`, локальные шаблоны и чарт. Якорь действует на **весь** исходящий
  трафик: центр, которому мы доверились, может выпустить сертификат на любое имя. Установка в другой
  юрисдикции должна получать это решение осознанно, а не вместе с нашим образом.
- **Нечитаемый ресурс останавливает старт**, а добавленные якоря пишутся в лог на `INFO`. Молча
  пропущенный сертификат неотличим от той самой ошибки `PKIX path building failed`, ради которой его
  и клали.
- **Обе половины — из одного экземпляра.** OkHttp принимает фабрику сокетов и trust manager парой и
  строит по второму свою очистку цепочки; собранные над разными наборами, они не согласуются и ломают
  рукопожатие. Поэтому `OutboundTrust` — бин, а не сборка по месту, и его берут все трое: пул Apache
  в `PublicOnlyHttp`, OkHttp в `WebhookTransport`, OkHttp Spring AI в `ModelFactory`.

Почему именно так и что отвергнуто — [decisions/outbound-tls-trust.md](../decisions/outbound-tls-trust.md).

## Чего гард не делает

Он не мешает воркеру или control-api открыть соединение куда угодно из другого кода — это
свойство сети, а не JVM. Egress-политика кластера живёт в `agimate-infra` и остаётся внешним
слоем защиты, а не заменяется этим.
