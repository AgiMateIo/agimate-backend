# MCP-сервер

Платформа отдаёт тулы агента наружу по Model Context Protocol: внешний AI-клиент (Claude Code,
Cursor, свой скрипт) подключается к `https://<host>/mcp` и получает те же инструменты, что есть у
агента, под теми же политиками.

## Модель: MCP-агент — это агент, у которого мозг снаружи

Отдельной сущности «ключ к MCP» нет. Субъектом прав остаётся агент: коннекшены к нему привязаны
(`agent_connections`), политики уточняют доступ (`agent_connection_policies`), а MCP — это
поверхность, на которой его ключ работает. Выбор «какие коннекшены отдать наружу» делается там же,
где и для любого агента, — привязками и политиками.

Тип `MCP` (см. [api-keys.md](api-keys.md)) говорит ровно одно: **push-транспорта нет**. Мозг тянет
работу сам, поэтому триггеров и каналов у такого агента не бывает. Во всём остальном он не отличается
от `CENTRIFUGO` и `WEBHOOK` — и `/mcp` открыт всем трём внешним типам: это один и тот же внешний мозг,
просто с разной дверью для входящих. Закрыт `/mcp` только для `GENERIC`: там цикл уже крутит наш
воркер, и внешний клиент был бы вторым мозгом на одной памяти.

## Ревизия и транспарент

Поддерживается **только `2026-07-28`** и только его stateless-форма.

| | |
|:--|:--|
| Эндпойнт | `POST /mcp` — один JSON-RPC запрос на запрос (батчи из протокола убраны) |
| Аутентификация | `Authorization: Bearer <ключ агента>`; принимается и legacy-заголовок `X-Api-Key` |
| `GET` / `DELETE` | `405` — потоков и сессий нет |
| `Mcp-Session-Id`, `Last-Event-ID` | игнорируются: не выдаются и не отражаются |
| `MCP-Protocol-Version` | если прислан и не равен `2026-07-28` — `400` |
| Методы | `initialize`, `ping`, `tools/list`, `tools/call` |
| Нотификации (запрос без `id`) | `202`, без тела |

Ответы **не заворачиваются** в `SuccessResponse` — конверт здесь протокольный. Ошибки уровня
транспорта (401/403/429) остаются HTTP-ответами: клиент читает статус.

Осознанно не поддержано: сессии и возобновляемые SSE (их нет в ревизии), таски, промпты, ресурсы,
пагинация листинга и уведомление `tools/list_changed` (без канала «сервер → клиент» его некуда
послать).

## Имена тулов

Клиент видит плоский список, поэтому имя строится как `<full_code>__<тул>`:
`mcp_context7__resolve-library-id`. Разделитель двойной, потому что одинарный `_` встречается внутри
самого `full_code`.

Символы вне `[a-zA-Z0-9_-]` заменяются на `_` (function-calling API клиентов иначе имя не примут),
имя длиннее 64 символов усекается с хвостом-хэшем. Обратное преобразование не делается: вызов
разрешается через каталог, а не разбором строки. Если два имени схлопнулись в одно, второе в листинг
не попадает — об этом пишется `WARN` с обоими именами.

## tools/call

1. Лимит вызовов по агенту (`INBOUND_RATE_LIMIT_MCP_CALLS_PER_MINUTE`, по умолчанию 120/мин) —
   до обращения к базе; превышение → `429`.
2. Имя ищется в каталоге. Каталога нет — значит тула нет или он запрещён политикой; в обоих случаях
   `-32602 Unknown tool`, без объяснения причины.
3. `AgentToolCallService` создаёт `tool_call_logs` (идемпотентность по `(agent_id, external_id)`,
   `external_id` генерирует сервер) и применяет ABAC вместе с `params_filter`.
4. Тул исполняется синхронно с бюджетом **60 с**. По таймауту клиент получает `isError`, а само
   исполнение продолжается и дописывает результат в лог.

Отказ политики на вызове и любая ошибка исполнения возвращаются как `isError: true` в успешном
JSON-RPC ответе: модель должна их увидеть и решить, что делать. Транспортная ошибка спрятала бы это.

Тул с объявленным `outputSchema` получает `structuredContent`; тот же payload дублируется текстом для
клиентов, которые структурированный вывод не читают.

## Что стоит знать

- **Каталог собирается на каждый запрос** — состояния между запросами нет по устройству протокола.
  Дорогая часть (решения политик) закэширована внутри `ConnectionAccessEvaluator`.
- **Тулы с отложенной доставкой бессмысленны.** `time.schedule` и джобы коннекторов адресуют ответ
  агенту, а доставлять MCP-агенту некуда — результат будет выброшен в лог. Такие коннекторы к
  MCP-агентам привязывать не нужно.
- **Петля через собственный mcp-коннектор.** У платформы есть и клиентский коннектор `mcp`; ничто не
  мешает подключить им же наш собственный `/mcp`. `McpTargetGuard` ловит SSRF, но не «сам себя» —
  пока это ограничение договорённости, а не кода.
