# Коннектор `web`: поиск в интернете и чтение страниц

Код: `web`. Пакет: `controlapi.connectors.internal.web`. Решение и разбор вариантов —
[decisions/web-search.md](../decisions/web-search.md).

Внутренний коннектор со строкой-режимом (одна на пользователя), подключается навыком `web`
(ленивый). Всем агентам подряд не раздаётся: поиск стоит платформе денег, а лишний тул мешает
слабым моделям.

## Что видит агент

| Тул | Что делает |
|---|---|
| `web_search(query, limit?, region?)` → `{results: [{title, url, snippet, date?}]}` | Yandex Search API; `limit` 1–20, по умолчанию 10; `region` — числовой код Яндекса, по умолчанию 225 (Россия); запрос не длиннее 400 символов — длиннее отказ, а не молчаливая обрезка |
| `web_fetch(url, maxChars?)` → `{url, title?, content, truncated}` | страница в markdown: сначала блок `Page metadata`, затем основной текст; `maxChars` 1000–60000, по умолчанию 20000 |

Оба тула — `openWorldHint = true`: воркер оборачивает их вывод в `<untrusted_tool_output>`, текст
страницы и сниппет для модели — данные, а не инструкции.

## Настройка оператором

| Свойство | Env | Что это |
|---|---|---|
| `app.connectors.web.yandex.api-key` | `APP_CONNECTORS_WEB_YANDEX_API_KEY` | ключ API сервисного аккаунта |
| `app.connectors.web.yandex.folder-id` | `APP_CONNECTORS_WEB_YANDEX_FOLDER_ID` | каталог Yandex Cloud |
| `app.connectors.web.search.daily-limit-per-user` | `APP_CONNECTORS_WEB_SEARCH_DAILY_LIMIT_PER_USER` | поисков на пользователя за скользящие сутки, по умолчанию 100; `0` — без лимита |

Ключ выпускается на **сервисный аккаунт с ролью `search-api.webSearch.user`** в том же каталоге, что
`folder-id`. Без ключа коннектор остаётся в каталоге: `web_search` отвечает «not configured», и
навык велит больше его не звать; `web_fetch` работает всегда.

**Лимит** считается по `tool_call_logs`: вызовы `web_search` пользователя за сутки с
`access_effect = ALLOW` и без ошибки (`ToolCallLogRepository.countSucceeded`). Строка текущего вызова
к моменту проверки уже записана, поэтому порог сравнивается через `>`. Запрещённые политикой,
упавшие и отклонённые самим лимитом вызовы квоту не тратят.

## Как устроен `web_fetch`

`WebPageReader` — единственный, кто знает порядок шагов:

1. **Сеть** — через `PublicOnlyHttp`: SSRF-резолвер и исходящий прокси. Редиректы (до 5) проходит
   сам, каждый переход — новое соединение, так что резолвер проверяет каждый адрес. Кириллический
   домен уходит в punycode, кириллица в пути — в percent-encoding. Общий дедлайн — 20 секунд на все
   переходы.
2. **Тело** — байтами, не больше 5 МБ распакованных (сверх — обрезается, а не отклоняется). Берутся
   `text/html`, `application/xhtml+xml`, `text/plain`; остальное — ошибка с типом. Кодировка —
   `charset` из заголовка, иначе jsoup смотрит BOM и `<meta charset>` (сайты в `windows-1251`).
3. **Антибот-стена** — распознаётся по заголовку страницы, по виджету капчи на странице почти без
   текста (одна reCAPTCHA в форме контактов стеной не считается) и по пустой странице на 401/403/498;
   пустая страница на 429/503 — просто статус, сайт лежит. Ответ — «сайт не пускает автоматические
   запросы», а не пересказ капчи. На 2026-09-30 так отвечают Ozon, Wildberries и главная РБК.
4. **Извлечение** (`ContentExtractor`, реализация `HeuristicContentExtractor`): метаданные из
   `meta`/`og:*`/`article:*`/`product:*` и JSON-LD (у статей — только дата и автор, у товаров и прочих
   данных — объект без картинок, ссылок и отзывов); вырезание обвязки (элемент со словом шума в классе
   уходит, только если в нём не больше половины текста страницы); основной блок — `article`,
   `main`, иначе по плотности текста. Меньше 200 символов текста — тела нет, ответ из метаданных.
5. **Markdown** (`MarkdownConverter`, реализация `JsoupMarkdownConverter`): заголовки, списки, цитаты,
   код, GFM-таблицы (с объединёнными ячейками — построчно), ссылки абсолютные, длиннее 300 символов —
   только текстом, картинки — `alt`.
6. **Обрезка** до `maxChars` на границе абзаца, `truncated: true`.

Страницы, собираемые JavaScript'ом, и PDF в первую версию не входят.

## Замена частей

`WebSearchBackend`, `ContentExtractor`, `MarkdownConverter` — интерфейсы с единственной реализацией-бином.
Своя реализация — свой бин с `@Primary`; свойство выбора поставщика
(`app.connectors.web.search.provider`) появится вместе со второй реализацией в проекте.
