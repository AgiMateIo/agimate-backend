# Файлы агента с версиями

Разбор начинался с двух идей — тула `html_page(content)`, отдающей страницу по ссылке, и коннектора
`file` с `list`/`save`. Здесь описана сделанная половина, и её критерий один: **что остаётся
неизменным, когда файл правят** — адрес, отправленное вложение, ссылка у агента в контексте.
Вторая половина, публикация страницы по постоянной ссылке, отложена до появления отдельного домена и
вынесена в [deferred/page-publishing.md](deferred/page-publishing.md); туда же уехал второй критерий
— где исполняется HTML, который написала модель.

**Короткий вывод.**

- `agf_` становится идентичностью документа, а не снимком содержимого: у файла есть версии, чтение
  по id отдаёт текущую, а места, где важно «что именно было отправлено», закрепляют номер версии.
- Один коннектор `files`: сохранить, поправить, прочитать, найти. Правка работает для любого
  текстового файла пользователя.

## Как это сделано у других

Авторство и публикация:

| | Авторство | Публикация | Правка | Адрес |
|---|---|---|---|---|
| **Claude Code** | `Read`/`Write`/`Edit` по пути; перед записью файл обязан быть прочитан | нет | `Edit` — точная замена строки | путь |
| **Anthropic text editor tool** | `view` с диапазоном строк, `create` | нет | `str_replace`, `insert` | путь |
| **ChatGPT Canvas** (`canmore`) | `create_textdoc(name, type, content)`, `code/html` показывается превью | нет | `update_textdoc`: пары «шаблон → замена», код переписывается целиком | документ разговора |
| **Claude Artifacts** | файл пишется обычным `Write` | `publish(file_path)` → URL; тот же путь — тот же URL, новая версия | правка файла и повторная публикация | свой поддомен на артефакт на `claudeusercontent.com` |
| **Manus** | `file_write` в песочнице | `deploy_expose_port` — временная ссылка, `deploy_apply_deployment` — постоянная | перезапись файла | поддомен развёртывания |

Версии:

| | Что стабильно | Версии | По умолчанию |
|---|---|---|---|
| **OpenAI Files, Anthropic Files API** | ничего — файл неизменяем | нет | — |
| **S3 с versioning** | ключ | `versionId` на каждую запись | последняя; конкретная — по `versionId` |
| **Google Drive** | `fileId` | revisions, старые чистятся, если не `keepForever` | последняя |
| **Claude Artifacts** | путь | версия на публикацию, конфликт при гонке | последняя |

Что из этого следует:

1. **Авторство и публикация — разные шаги.** Публикация — явное действие, а не побочный эффект
   сохранения.
2. **Адрес переживает правки.** Меняется содержимое под адресом, адрес нет.
3. **Файловые API LLM-платформ неизменяемы, хранилища документов версионируют.** Первые — вложения
   к запросу, вторые — долгоживущие документы. Мы переходим во вторую категорию в тот момент, когда
   появляется «поправь документ».
4. **Чужой HTML отдаётся с чужого домена.** GitHub — `githubusercontent.com`, Google —
   `googleusercontent.com`, Claude — `claudeusercontent.com` с CSP `connect-src 'self'`.
5. **Между моделью и браузером страницу никто не проверяет.** Разбор Pluto Security: в 10 из 85
   попыток prompt injection агент вписал секреты в скрытый блок публикуемой страницы. Защита — не
   проверка содержимого, а то, что страница ничего не может отправить наружу, и владелец видит, что
   опубликовано.
6. **Точечная правка — замена строки** с требованием единственного вхождения.

## Версии файла

### Смысл идентификатора

`agf_` — документ. Любой, кто получает файл по id (тул, gRPC `GetFile`, листинг), получает текущую
версию. Номер версии закрепляется только там, где записано «что было отправлено».

| Место | Поведение |
|---|---|
| Тулы, `read_image`, импорт в sheets | текущая версия, без изменений в коде |
| `[[attach:agf_…]]` | прикладывает версию, текущую на момент ответа |
| Telegram | ничего не нужно: байты уезжают в момент отправки |
| Webchat parts (`WebchatAttachment`) | новое поле `version`; у старых записей его нет — это v1 |
| Входящие вложения (`FilePart` в `inbound_parts`) | новое поле `version` и такое же в `GetFileRequest`, иначе воркер всё равно скачает текущие байты: история рана показывает модели то изображение, которое прислали. Поля опциональные — сначала деплой control-api, drain не нужен |
| Подписанная ссылка `/files/{id}` | подпись по `fileId\|version\|exp`: кеш `max-age` не выдаст старые байты под новым номером |
| `file_references` | остаётся на уровне файла |

### Схема

- **`files`** — документ и копия его текущей версии. Добавляются `version` (номер текущей) и
  `claimed_version` (см. «Запись новой версии»); `mime`,
  `size`, `sha256`, `agent_id`, `origin` описывают текущую версию. Потребители, читающие `files`,
  не меняются.
- **`file_versions`** — полный журнал версий, текущая включена: `file_id`, `version`, `mime`,
  `size`, `sha256`, `agent_id`, `origin`, `created_at`; уникальность `(file_id, version)`, удаление
  каскадом вместе с файлом. Миграция заводит v1 каждому существующему файлу.

Копия текущей версии в `files` — денормализация ради того, чтобы десяток потребителей не узнал о
версиях. Журнал целиком в одной таблице нужен закреплённому чтению и квоте: и то и другое смотрит в
одно место.

- **Ключ blob.** У v1 остаётся нынешний `userId/agf_…` — существующие объекты не переносятся.
  С v2 — соседний ключ `userId/agf_….v{n}`, а не вложенный `agf_…/v{n}`: `LocalBlobStore` кладёт
  ключ прямым путём на диск, и `agf_…` не может быть одновременно файлом v1 и каталогом v2.
  Правило живёт в `FileLink`.
- **Очистка** удаляет blob каждой выданной попытки (`1..claimed_version`): каскад в базе убирает
  строки, но не объекты.
- **Квота** считается по `file_versions.created_at`: перезапись старого файла иначе не попала бы в
  суточный лимит, потому что `files.created_at` у него давний.
- **История не ограничена.** Версии уходят вместе с файлом, так что их держит TTL. Потолок, если
  понадобится, — одно правило очистки без изменения схемы; понадобится он с бессрочными файлами,
  то есть вместе с [публикацией](deferred/page-publishing.md).

### Запись новой версии

Одновременная правка одного файла редка, и ей не нужно сливаться: записи идут по одной, а вторая
получает отказ. Отказ должен прийти **до** заливки — если оба писателя возьмут номер `version + 1`,
они зальют байты под один ключ, и проигравший перезапишет blob победителя раньше, чем узнает, что
проиграл. Поэтому номер попытки выдаётся отдельно от номера версии — `files.claimed_version`,
последний выданный номер, который никогда не выдаётся повторно:

1. **Захват** — короткий автокоммит: `claimed_version + 1` при условии
   `version = :прочитанная AND (claimed_version = version OR updated_at < now() - 5 минут)`.
   Ноль строк — `ConnectorException` «файл сейчас пишет другой вызов или он изменился»; заливки не
   было, агент перечитывает и повторяет сам.
2. **Заливка** под `agf_….v{n}`: номер принадлежит только этой попытке.
3. **Коммит** одной инструкцией: `UPDATE files SET version = n, … WHERE claimed_version = n` и в том
   же CTE `INSERT file_versions`. Ноль строк — попытку перехватили как зависшую: удалить **свой**
   blob и отказать.

Упавшая посреди записи попытка держит файл пять минут, дальше захват выдаёт следующий номер —
в нумерации остаётся дыра, данные целы. Время захвата — `updated_at`: любое обновление строки
в это окно лишь сдвигает его. Закреплённое чтение версии требует строку в `file_versions`, у сироты
её нет; очистка удаляет ключи `1..claimed_version`.

Отвергнуто: резерв номера строкой `file_versions` со статусом (статус и подметание резервов ради
того же результата), блокировка строки на время заливки (транзакция на сетевом PUT), ключ по
`sha256` (закрепление по хешу, сироты проигравших не удалить — тем же ключом может пользоваться
старая версия), условная запись в хранилище (`If-None-Match` у cloud.ru не проверить, сирота
занимает номер навсегда).

Если `sha256` и `mime` не изменились, версия не создаётся — переименование пишется в `files.name`
само по себе: имя принадлежит документу, а не версии. Срок продлевается и в этом случае. Ни одна из
записей не проходит по файлу с `expires_at <= now`: удаление из UI — это именно такой срок, и правка,
начатая до удаления, не должна вернуть файл. Запись продлевает `expires_at` до
`max(текущий, now + ttl)`: правленый файл не должен истечь через день после правки.

Перезаписать можно любой файл пользователя, включая загруженные. Новая версия несёт свой `mime`.

## Коннектор `files`

Внутренний коннектор, строка-режим, `ConnectorTraits.internal()`. Владельца-правила нет: граница —
`userId`, сессия — явный адрес вызова (строка «правила нет» в таблице осей
[connectors.md](../architecture/connectors.md), вывод — в class-javadoc). Доступ даёт навык
`seed/skills/<lang>/files/SKILL.md` с `connectors: [files]` и `disclosure: lazy`; пресеты сеются
только если их нет, так что новый навык получат новые агенты.

| Тул | Что делает | Хинты |
|---|---|---|
| `save_file(content, name?, file_id?)` | без `file_id` — новый файл, `name` обязателен; с `file_id` — новая версия целиком, `name` переименовывает, не задан — имя прежнее. `mime` из расширения имени (`.html`, `.md`, `.csv`, `.json`, иначе `text/plain`). Потолок аргумента — порядка 1 МБ | `destructive=false`, `openWorld=false` |
| `edit_file(file_id, edits[{old_text, new_text}])` | замены по порядку; каждая `old_text` встречается ровно один раз в тексте после предыдущих замен, иначе `ConnectorException` с числом вхождений и ничего не пишется. Только текстовый `mime` | `destructive=false`, `openWorld=false` |
| `read_file(file_id, offset?, limit?)` | окно по строкам с потолком символов на ответ (минифицированный HTML бывает одной строкой), признак продолжения. Нетекстовый `mime` — `ConnectorException` с подсказкой про `media.read_image` | `readOnly=true`, `idempotent=true`, `openWorld=false` |
| `list_files(all_conversations?, name?)` | как `platform.list_files` | `readOnly=true`, `idempotent=true`, `openWorld=false` |

Результат `save_file` и `edit_file` — `{"file": {id, name, mime, size, version}}`, тот же вид, что у
`sheets.export`.

- **`platform.list_files` не трогаем.** Общая часть — вызов `StoredFileRepository.findVisible`, она
  и так одна. Удалять тул из `platform` нельзя: уже засеянные агенты `platform-admin` его потеряют.
- **`delete_file` нет.** Удаление файлов пользователя агентом необратимо, в UI оно уже есть.
- **Замены — отдельный класс без Spring.**
- **Доставка** — маркер `[[attach:…]]`. Навык говорит прямо: в ране без канала или в канале без
  вложений (ACP) файл пользователю не уйдёт, и о нём надо сказать словами.

Показ `text/html`-вложения прямо в webchat (`<iframe srcdoc sandbox="allow-scripts">` без
`allow-same-origin`) — необязательная задача фронта; CORS у `/files/{id}` уже открыт для всех
цепочек безопасности.

## Отвергнутые варианты

- **Один коннектор `html_page(content)` без `files`** — дублирует хранение и чтение; нельзя
  опубликовать файл, сделанный другим тулом.
- **Неизменяемый `agf_` и изменяемая страница-указатель поверх** (прежняя редакция документа) —
  стабильная идентичность оказывается только у страниц; `edit_file` для остальных файлов потом
  повторил бы ту же механику.
- **Перезапись байтов под тем же ключом без версий** — уже доставленное вложение задним числом
  стало бы другим, ломаются `sha256` и кеш подписанных ссылок.
- **`files` только идентичность, содержимое целиком в `file_versions`** — чище по форме, но
  переписывает всех потребителей и горячую таблицу ради того же результата.

Варианты, отвергнутые вокруг публикации страницы, — в
[deferred/page-publishing.md](deferred/page-publishing.md).
