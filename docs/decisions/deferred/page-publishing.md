# Публикация страницы по ссылке

Вторая половина разбора [files-and-pages.md](../files-and-pages.md): агент сохраняет HTML файлом и
отдаёт его пользователю **по постоянной ссылке**. Первая половина — версии файлов и коннектор
`files` — сделана; эта отложена, и упирается она в одну вещь: **нужен отдельный регистрируемый
домен**, а заводить его ради одной задачи пока несоразмерно.

Разбор доведён до схемы и заголовков; когда домен появится, работа начинается с «Плана» внизу.

**Короткий вывод.** Страница отдаётся с отдельного регистрируемого домена, адрес постоянный,
содержимое — всегда текущая версия файла. Вариант «отдать `/files/{id}` с `text/html`» отвергается
целиком.

## Почему не `/files/{id}` с `text/html`

- `FileContentHeaders` **намеренно** отдаёт активные типы (`text/html`, SVG, XML, JS) как
  `application/octet-stream` и вложением, а `FileHttpResponses` ставит
  `Content-Security-Policy: sandbox; default-src 'none'`. Снять это ради страниц — снять защиту со
  всех файлов, включая присланные пользователями.
- Вход живёт на `agimate.io`, и HttpOnly-cookie user-api стоят на домене продукта. Страница на любом
  его поддомене — same-site: браузер отправит с её запросами cookie, `SameSite` не помогает.
- Подписанная ссылка живёт 15 минут, а у страницы адрес должен быть постоянным.

## Модель

Колонка `files.public_token`: nullable, уникальный констрейнт. Опубликовать — выдать токен,
снять — стереть. Одна ссылка на файл, заголовок страницы — имя файла. Отдельная таблица появится,
когда у ссылки будут собственные настройки (срок, пароль); сейчас их нет.

- **Токен, а не `id`.** В `UUIDUtils.generateUUIDv8` 48 бит — монотонный счётчик от времени и 16 —
  контрольная сумма, случайных остаётся 58. Токен — 128 бит из `SecureRandom` в URL-безопасной
  кодировке.
- **Опубликованный файл бессрочен.** `files.expires_at` становится nullable: `null` — не истекает.
  Очистка по `expires_at < now` пропускает `null` без правок, `findReadable` добавляет
  `IS NULL`. Публикация ставит `null`, снятие — `now + default-ttl`: исходный срок не хранится, и
  загрузка с 90 днями после снятия проживёт 7.
- **Удаление файла снимает страницу само.** Удаление в UI ставит `expires_at = now`, а `/p/{token}`
  отдаёт только не истёкший файл — второго пути «удалить и отозвать ссылку» не нужно.

## Тулы

| Тул | Что делает | Хинты |
|---|---|---|
| `publish_page(file_id)` | выдаёт токен, если его нет, и возвращает `{file_id, url}`; повторный вызов отдаёт ту же ссылку | `destructive=false`, `idempotent=true`, `openWorld=true` |
| `unpublish_page(file_id)` | стирает токен | `destructive=true`, `idempotent=true`, `openWorld=false` |
| `list_pages()` | опубликованные файлы пользователя | `readOnly=true`, `idempotent=true`, `openWorld=false` |

Правка — `edit_file` или `save_file(…, file_id)`: ссылка сразу показывает новую версию. Навык
`files` дополняется разделом о публикации, отдельного навыка нет.

**Установка без домена страниц.** Пока `app.pages.base-url` не задан — а на своей установке его
может не быть вовсе, — фасад `FilesConnectorService` не отдаёт три тула из `getTools()`
(переопределение, как у MCP), а сами методы на прямой вызов отвечают `ConnectorException`. Агент
не видит тул, который не сработает; раздел навыка оговаривает «если тулы публикации доступны».

**Доступ.** Модель ABAC разрешает всё, что не запрещено, поэтому привязка `files` даёт и
публикацию. Это приемлемо:

- ссылка сама по себе не утечка: токен на 128 бит, `noindex`, и чтобы увести данные, атакующему
  нужно ещё получить ссылку — отдельным каналом, который закрывается своими правилами;
- владелец видит опубликованное в листинге и снимает одним действием;
- кому публикация не нужна — правило `deny` на `publish_page` в привязке, а навык, которому она
  не нужна, объявляет `tools: {deny: [publish_page]}` в требовании к коннектору.

Проверки «публиковать только файлы, созданные агентом» нет: агент под prompt injection прочитает
чужой HTML и пересохранит его своим. Защита — домен, CSP и листинг у владельца.

## Отдача

`GET /p/{token}` в control-api, только на хосте `app.pages.base-url`; запрос с другим `Host` получает
404, так что страница недостижима с домена API. Отдаётся текущая версия, если файл не истёк и её
`mime` — `text/html`, иначе 404.

Хост — **отдельный регистрируемый домен**, не поддомен `agimate.io` (`files.agimate.io` не годится):

- cookie продукта стоят на `agimate.io`, и страница на его поддомене — same-site;
- первая выложенная агентом фишинговая страница попадёт в Google Safe Browsing, и под блокировку уйдёт
  весь `agimate.io` вместе со входом;
- `/files/{id}` уже есть на API и значит другое.

Guard на старте не делаем: домен cookie — настройка user-api, control-api его не видит. Требование
к домену записывается в `docs/operations/`.

Заголовки:

```
Content-Type: text/html; charset=utf-8
Content-Security-Policy: sandbox allow-scripts allow-popups; default-src 'none';
  script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:;
  font-src data:; connect-src 'none'; form-action 'none'; frame-ancestors 'none'
X-Robots-Tag: noindex, nofollow
Referrer-Policy: no-referrer
X-Content-Type-Options: nosniff
Cache-Control: no-cache
ETag: <sha256 текущей версии>
```

- `sandbox` без `allow-same-origin` делает origin документа непрозрачным даже при открытии
  напрямую: ни cookie, ни `localStorage`. Вторая линия, если домен настроят неверно.
- `connect-src 'none'`, `img-src` без внешних хостов и `form-action 'none'` отрезают отправку
  данных наружу. Цена: страница не тянет живые данные, всё зашивается в HTML при генерации. Утечка
  переходом по ссылке (`location = …?data=`) CSP не закрывается — остаточный риск.
- Скриптов с CDN нет; графики — инлайн-SVG. Добавим allowlist, когда попросят.
- `frame-ancestors 'none'`, пока фронт страницы не встраивает.

## Надзор владельца

Листинг `/manage/files/` получает поле `publicUrl` и фильтр `published`; снятие —
`DELETE /manage/files/{id}/public-link`. Это не «на будущее»: публикация — действие наружу, и
владелец должен видеть и снимать то, что агент выложил без него. Без экрана на фронте смысла нет —
дельта в `tmpspec/` входит в фазу.

## Отвергнутые варианты

- **`/files/{id}` с `text/html`** — см. выше.
- **Таблица `pages`** — одной ссылки на файл достаточно; своей жизни у ссылки пока нет.
- **Отдельный коннектор `pages`** — рассматривался ради того, чтобы привязка файлов не давала
  публикацию молча. Но для этого уже есть правило `deny` на тул и `tools.deny` в требовании навыка,
  а второй коннектор — это второй фасад, навык, перевод, строка в каталоге и связка «pages без files
  бесполезен» ради одного запрета.
- **HTML в `TEXT`-колонке** — отдельный путь квоты и размера мимо blob store.
- **Presigned-ссылка S3 для страниц** — заголовками не управляем, в ключе виден `userId`, срок
  15 минут.
- **Приватные страницы со входом владельца** — нужна сессия на чужом домене. Ссылка-ключ,
  `noindex` и снятие с публикации покрывают «показать отчёт».
- **Поддомен `agimate.io` для страниц** — см. «Отдача».
