# Прокси инференса для внешних агентов (отложено)

Единственный способ дать внешнему агенту **платформенную** модель, не выдавая ему ключ.

## Почему это вообще вопрос

Внутри платформы модель выдаётся через одну воронку — `LlmCredentialsResolver`: выбор
провайдера/модели → `enabled` → квота (`LlmQuotaService`) → расшифровка ключа. Её потребитель —
наш воркер по gRPC (`GetLlmCredentials`), и он же возвращает расход (`ReportLlmUsage`). Квота и учёт
держатся на том, что ключ уходит доверенному коду, который отчитывается.

Внешний агент (`CENTRIFUGO`, `WEBHOOK`, `MCP`) доверенным кодом не является. Ключ, выданный ему один
раз, работает вечно и вне любого нашего учёта: проверка квоты **на выдаче** ничего не стоит, потому
что после выдачи вызовы идут мимо нас. Поэтому `/agent/llm/` отдаёт только метаданные привязки
(провайдер, модель), а ключей наружу не выдаётся никому — см. [api-keys.md](../../contracts/api-keys.md).

Следствие сегодняшнего состояния: внешний агент работает **на своей копии ключа**. Для агента на
своём провайдере это ничего не меняет (ключ он вводил сам). Для платформенных моделей с квотами —
означает, что они внешним агентам недоступны.

## Что нужно сделать, когда вернёмся

OpenAI-совместимая ручка на нашей стороне (`POST /agent/llm/chat/completions` или отдельный хост),
которая:

1. аутентифицирует агента его же ключом (`ROLE_AGENT`);
2. резолвит провайдера и модель через тот же `LlmCredentialsResolver` — не заводя второй путь;
3. проверяет квоту **до** вызова и списывает расход **после**, по ответу провайдера;
4. проксирует запрос, включая стриминг (SSE), и `extra_body` из настроек провайдера/модели.

Тогда квота становится настоящей: она стоит на каждом вызове, а не на выдаче.

## Открытые вопросы

- **Стриминг и таймауты.** Долгий SSE-ответ держит наш поток; на воркере этой проблемы нет.
- **Мультимодальность.** `resolveForCapability` (медиа) устроен иначе — прокси должен либо покрыть и
  его, либо честно ограничиться CHAT.
- **Абьюз.** Прокси — это открытая наружу LLM-ручка; нужен rate limit по агенту сверх квоты и
  потолок на размер запроса.
- **Не мимикрировать под провайдера полностью.** Совместимость с OpenAI-схемой соблазняет
  проксировать всё подряд; безопаснее принимать известный набор полей, а неизвестные отбрасывать.
