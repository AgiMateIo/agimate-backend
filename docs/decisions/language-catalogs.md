# Каталоги пресетов и навыков по языкам

Сейчас системный контент существует в одном языке на инсталляцию: `app.content.language` выбирает
папку `seed/<kind>/<lang>/`, бутстрапы сидируют её один раз, и база держит один набор
([content-language.md](../architecture/content-language.md)). Нужно иное: русскоязычной и
англоязычной аудитории — свои агенты, наборы пресетов и навыков на разных языках могут **различаться**,
а выбирает их переключатель языка в интерфейсе. Первая цель, ради которой это затеяно, — публичный
каталог пресетов, но он во вторую фазу.

## Почему пересмотрено решение от 2026-07-25

Тогда был отвергнут вариант «по строке на язык» с `unique (name, language)`. Он задумывался как
**перевод одной сущности**: у пресета `coder` две строки, и чтение должно выбирать язык с откатом на
другой. На этом он и развалился — фильтр в `SkillSpecs`, расщепление админского листинга, резолв
навыков пресета по языку, невозможность отката в постраничном листинге.

Теперь языковые версии — **самостоятельные записи**, а не переводы друг друга. Отката между языками
нет, поэтому большая часть тех проблем не возникает: листинг — фильтр, привязки по `id` не видят
языка, пагинация не врёт.

Отвергнуты:

- **Таблица переводов** (`skill_texts(skill_id, lang, …)`) — хороша, когда набор общий и различаются
  только тексты; «есть только на русском» в ней — костыль.
- **Гибрид** «запись + `languages text[]` + переводы» — избыточен под задачу.
- **Системный контент только в classpath** — ломает правку через Manage API, от похожей схемы уже
  отказывались.

## Модель

- Колонка `language` (`ContentLanguage`, TEXT): у пресета обязательна, у навыка допускает `NULL` —
  «без языка». Без языка — пользовательские навыки и системные, годные для любой аудитории.
- `name` — код без языкового префикса. Префикс (`ru.coder`) отвергнут: язык жил бы в двух местах, а
  имя навыка видит модель.
- Уникальность:
  - навык — `(user_id, name, language) NULLS NOT DISTINCT WHERE deleted_at IS NULL` вместо
    `uq_skills_user_id_name_active`;
  - пресет — `uq_agent_presets_name_language` вместо `uq_agent_presets_name`.
- `version` у каждой языковой записи свой.

## Поиск по имени

Всегда по паре «имя + язык»: сначала язык контекста, потом навыки без языка. Язык контекста:

- навыки пресета (`skill_names`) — язык пресета; ссылка на навык чужого языка не поддерживается —
  навык, нужный в обоих каталогах и не переведённый, помечается «без языка». Смешивать языки в
  промпте одного агента не хотим;
- платформенная автопривязка (`TEAM_SKILL_NAME` и другие) — язык агента.

Агенту нельзя привязать два навыка с одинаковым именем: skill-loader ищет по имени.

## Язык агента

Новая колонка `agents.language` (`NULL` — дефолтный язык). Заполняется при создании: язык пресета,
если агент создан из пресета, иначе язык запроса. Переключение языка в интерфейсе на созданных агентов
не влияет.

## Язык запроса

Заголовок `Accept-Language`, а не GET-параметр: сигнатуры эндпойнтов не меняются, действует сразу на
всё. Вне HTTP-запроса и при неподдерживаемом языке — `app.content.language`, который становится
дефолтом, а не языком инсталляции. Для будущего публичного кэша достаточно `Vary: Accept-Language`.

Заголовок читает `ContentLanguageResolver` напрямую, а не Spring'овый `LocaleResolver`: локаль
резолвера управляет и сообщениями валидации, и дефолт, выставленный там, переключил бы их всем
клиентам без заголовка. Сопоставление — по основному сабтегу в порядке веса: `Locale.filterTags` по
RFC 4647 не сводит `en-US` к `en`, а браузер может прислать только региональную форму.

Браузер шлёт язык ОС, а не интерфейса, поэтому фронт ставит заголовок явно из локали интерфейса.

Язык запроса — для того, что видит человек, и для языка нового агента. Тела навыков и инструкции в ране
берутся из записей, привязанных к агенту, а не по заголовку.

## Выкатка

- Миграция помечает существующие системные навыки и все пресеты языком инсталляции: его знает только
  Spring, поэтому он передаётся в Liquibase параметром (`spring.liquibase.parameters.contentLanguage`).
- На первом старте бутстрапы досеивают второй язык. Галерея и листинги при этом не меняются: они
  показывают каталог `app.content.language`.
- Проверено на клоне локальной базы: 19 навыков и 12 пресетов на языке инсталляции, столько же
  досеяно на втором, повторный старт ничего не сеет, дубль безъязыкового навыка отбивает индекс.

## План

**Схема**
- [x] Миграция `skills.language` (TEXT NULL): системным строкам язык инсталляции, пользовательским
  `NULL`; ключ пересоздать.
- [x] Миграция `agent_presets.language` (TEXT NOT NULL, существующим — язык инсталляции); ключ
  пересоздать.
- [x] Миграция `agents.language` (TEXT NULL).
- [x] Сущности и `@Table(uniqueConstraints)`.

**Язык запроса**
- [x] `ContentLanguageResolver`: язык из `Accept-Language`, вне HTTP-запроса и без совпадения —
  `app.content.language`.

**Поиск по имени**
- [x] Методы репозиториев принимают язык: язык контекста, потом без языка
  (`SkillRepository.findByNamesInLanguage`).
- [x] Навыки пресета резолвятся и валидируются в языке пресета.
- [x] Автопривязка навыка команды — по языку агента.
- [x] Запрет двух навыков с одинаковым именем при привязке (409).

**Создание агента**
- [x] `agents.language` из пресета, иначе из языка запроса. Пресет ищется в каталоге галереи —
  дефолтном, пока галерея не следует за запросом.

**Сиды**
- [x] `SystemSkillBootstrap` и `SystemPresetBootstrap` обходят все `seed/<kind>/<lang>/`, ключ —
  пара «имя + язык»; недостающий язык досеивается на засеянной инсталляции. Отката на `en` в
  `SeedContentLocator` больше нет.
- [x] `SeedContentParityTest` удалён; `SystemPresetBootstrapTest` проверяет, что навыки пресета есть в
  его языке.

**Тесты**
- [x] Поиск с откатом на «без языка», разбор заголовка и дефолт, язык агента, запрет одноимённых.
- [x] Новые ограничения — на клоне локальной базы. Клон прод-базы — перед выкаткой.

## Не в этой фазе

- Листинги по языку запроса: галерея пресетов, навыки (и в platform-коннекторе), подписи коннекторов
  и таксономии — сделано во второй фазе, [public-catalog.md](public-catalog.md).
- `language` в DTO админки. Во второй фазе админ создаёт пресет или системный навык в языке запроса
  и видит таблицу (`/manage/agent-presets/all/`) одного языка: два `coder` в ней было бы не различить.
- Публичный каталог `/public/catalog/...`.
- `language` в DTO запросов и ответов.
- Язык у пользовательских навыков.
