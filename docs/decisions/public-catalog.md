# Публичный каталог и каталоги по языку интерфейса

Нужна страница каталога на сайте для поискового продвижения: пресеты агентов и навыки, доступные без
авторизации. Вторая фаза [language-catalogs.md](language-catalogs.md): каталог и все листинги в
`/manage` следуют за языком интерфейса — заголовком `Accept-Language`.

## Публичный каталог

Отдельный префикс `/control/public/catalog` в публичной security-цепочке (`permitAll`). Открывать
`/manage` наружу не стали: там сессия пользователя, админские поля и записи, которые не должны
попадать в выдачу.

Эндпойнты, все `GET`:

| Путь | Что отдаёт |
|---|---|
| `agent-presets/` | включённые пресеты языка запроса |
| `agent-presets/{name}` | пресет, его навыки с описаниями, коннекторы с именами |
| `skills/` | системные публичные навыки языка запроса и без языка |
| `skills/{name}` | навык, его коннекторы, пресеты, в которые он входит |
| `taxonomy/` | подписи категорий и тегов |
| `connectors/` | `code`, `name`, `description` |

Не отдаются инструкции пресета и тело навыка (`md_content`) — это и есть продукт. Также не отдаются
`connectors.params`, `id`, `userId`, `version`, даты. Ответы — отдельные публичные DTO, а не урезанные
админские: новое поле в админке не должно молча утечь наружу.

Навыки — только системные и публичные (владелец — платформа). У пресета показываются только навыки,
которые есть в каталоге: снятый с публикации навык не получит ссылку, ведущую в 404. Публичный навык пользователя не модерирован, а
`skills/{name}` у двух пользователей с одинаковым именем был бы неоднозначен.

Страница отдельной сущности нужна поисковику: список не индексируется как содержание. Перелинковка
пресет ↔ навык ↔ коннектор — туда же.

Идентификатор в адресе — `name`: он стабилен и читаем. CTA ведёт на регистрацию с `?preset=<name>`.

### Язык

Язык — в URL фронта (`/ru/catalog/...`, `/en/catalog/...`): поисковик не шлёт осмысленный
`Accept-Language`. Сервер фронта ставит заголовок из локали маршрута, бэкенду этого достаточно.

Языковые записи самостоятельные, поэтому пара для `hreflang` есть не всегда — фронт связывает версии
по одинаковому `name`, если она существует в обоих каталогах.

### Кэш

`Cache-Control: public, max-age=…` и `Vary: Accept-Language`. На фронте — ISR с ревалидацией: новый
пресет появляется без деплоя. Кэш заодно гасит нагрузку от анонимных запросов. Sitemap фронт строит из
списков по каждому языку — отдельный эндпойнт не нужен.

## Листинги `/manage` по языку запроса

Путь и DTO те же, меняется язык ответа:

- `GET /manage/agent-presets/` и `/all/` — каталог языка запроса.
- `POST /manage/agents/` — пресет ищется в языке запроса. Иначе каталог покажет английский `coder`, а
  агент создастся из русского.
- `GET /manage/skills/?scope=PUBLIC` — навыки языка запроса и без языка. Свои навыки — без фильтра.
- `GET /manage/connectors/`, `/{code}` — имя и описание по языку запроса поверх колонок БД.
- `GET /manage/taxonomy/` — подписи по языку запроса.
- `list_presets`, `list_skills` и `create_agent` platform-коннектора — по языку агента, а не запроса:
  тул вызывается в ране, где заголовка нет. Язык каталога передаётся в `AgentCreateCommand` с
  границы, а не берётся из заголовка внутри сервиса.

Заголовок читает `ContentLanguageResolver.requestLanguage()`, и он же дописывает в ответ
`Vary: Accept-Language` — зависимость объявляется там, где возникает, а не списком путей.

`ConnectorTexts` и `TaxonomyTexts` держат бандлы всех языков, а не один. Колонки `connectors.name` и
`description` остаются на дефолтном языке: по ним идёт поиск `?search=` и порядок листинга. Ответ
переводит `ConnectorLabels`, и откат перевода идёт к английскому в коде — хендлера или
`StaticConnector` (`app`, `claude-code`), — а не к колонке: на RU-инсталляции она русская.

Админ создаёт пресет и системный навык в языке запроса (`POST /manage/agent-presets/`,
`POST /manage/skills/system`). Иначе с английским интерфейсом он создаёт пресет, которого не видит в
своей таблице.

## План

**Языки в `/manage`**
- [x] `ConnectorTexts`, `TaxonomyTexts` — бандлы всех языков, текст по запрошенному.
- [x] Галерея, админская таблица, создание агента по пресету — язык запроса.
- [x] Публичный листинг навыков — язык запроса; `list_presets`/`list_skills`/`create_agent` — язык
  агента.
- [x] Коннекторы и таксономия — подписи по языку запроса.
- [x] Создание пресета и системного навыка админом — язык запроса.
- [x] `Vary: Accept-Language` на ответах, прочитавших заголовок.
- [x] Проверено на своём инстансе: галерея, навыки, `app`/`time`, таксономия под `ru` и `en`;
  агент из `coder` получает язык заголовка.

**Публичный каталог**
- [x] Контроллер `/public/catalog`, публичные DTO, путь в `permitAll`.
- [x] Шесть эндпойнтов, `Cache-Control: max-age=300, public` и `Vary: Accept-Language`.
- [x] Проверено на своём инстансе без токена: оба языка, 404 на неизвестный код, `/manage` по-прежнему
  401, в ответах нет инструкций и тел.

**Тесты**

- [x] Навыки пресета — только из каталога, языковая версия важнее безъязыковой, выключенный пресет и
  неизвестный навык — 404. Пользовательские навыки отсекает запрос (`ownedBy` платформы).

**Документация**

## Не в этой фазе

- Модерация пользовательских навыков: флаг «промодерирован», сбрасывается при изменении навыка.
  Тогда они смогут попасть в публичный каталог.
- Публичные пресеты, созданные пользователями.
- `language` в DTO админки и язык у пользовательских навыков.
- Поиск `?search=` по коннекторам на языке запроса.
- Имена коннекторов в `list_connectors`/`get_connector` platform-коннектора и в плане привязки навыка
  (`AgentSkillService`) — из колонок, то есть на дефолтном языке.
